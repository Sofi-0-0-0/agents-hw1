# Spec delta: tracker

## ADDED Requirements

### Requirement: Автономная поставка
Трекер MUST поставляться одним файлом `tracker-v2.html`, в котором CSS и JavaScript встроены внутрь. Файл MUST NOT подключать CDN, внешние библиотеки, внешние шрифты и изображения. Он MUST NOT требовать API-ключей и MUST NOT выполнять сетевые запросы.

#### Scenario: Открытие без сети
- **WHEN** файл открыт локально (`file://`) при отключённой сети
- **THEN** трекер полностью работает: показан стартовый пример, работают добавление, удаление, переключение, фильтр и сводка

#### Scenario: Отсутствие внешних ресурсов
- **WHEN** просматривается исходный текст файла
- **THEN** в нём нет `<script src>`, `<link href>` на внешние адреса, `@import` с внешними адресами, `fetch`/`XMLHttpRequest` и ключей API

### Requirement: Модель задачи и стартовые данные
Каждая задача MUST иметь поля `id` (уникальный в пределах сессии), `title` (строка), `hours` (число), `done` (boolean). При старте трекер MUST содержать ровно три задачи по порядку: «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`.

#### Scenario: Стартовые итоги
- **WHEN** трекер только открыт
- **THEN** список показывает три задачи, всего 8 ч, выполнено 2 ч, прогресс 25%

### Requirement: Добавление задачи
Отправка формы с валидными данными MUST добавлять новую задачу в данные с новым уникальным `id`, `title` после trim, `hours` из поля и `done=false`. Сводка MUST пересчитываться.

#### Scenario: Успешное добавление
- **WHEN** на стартовых данных добавлена задача «Тест» с часами 1,5
- **THEN** в списке четыре задачи, всего 9,5 ч, выполнено 2 ч, прогресс 21%

#### Scenario: Название сохраняется без крайних пробелов
- **WHEN** введено название «  Конспект  » и валидные часы
- **THEN** добавленная задача имеет название «Конспект»

### Requirement: Удаление задачи
Кнопка удаления MUST убирать задачу из данных, а не только скрывать её. Сводка MUST пересчитываться.

#### Scenario: Удаление выполненной задачи
- **WHEN** на стартовых данных удалена «Чтение»
- **THEN** всего 6 ч, выполнено 0 ч, прогресс 0%

#### Scenario: Удалены все задачи
- **WHEN** удалены все задачи
- **THEN** итог 0 ч, выполнено 0 ч, прогресс 0%, нигде не выводятся `NaN` или `Infinity`

### Requirement: Переключение готовности
Переключатель `done` MUST менять значение поля `done` задачи в данных. Сводка MUST пересчитываться.

#### Scenario: «Практика» отмечена готовой
- **WHEN** на стартовых данных «Практика» отмечена готовой
- **THEN** выполнено 6 ч из 8 ч, прогресс 75%

#### Scenario: Снятие отметки
- **WHEN** у «Чтения» снята отметка готовности на стартовых данных
- **THEN** выполнено 0 ч из 8 ч, прогресс 0%

### Requirement: Валидация названия
Название MUST считаться валидным, только если после trim оно непустое.

#### Scenario: Пустое название
- **WHEN** форма отправлена с пустым названием или названием только из пробелов
- **THEN** задача не добавляется, рядом с полем названия видна ошибка

### Requirement: Валидация часов
Часы MUST быть числом в диапазоне от 0,5 до 24 включительно с шагом 0,5. В качестве десятичного разделителя принимаются запятая и точка. Пустое значение (в том числе из одних пробелов) MUST NOT приравниваться к нулю и MUST давать отдельную ошибку «не указано».

#### Scenario: Пустые часы
- **WHEN** форма отправлена с пустым полем часов
- **THEN** задача не добавляется, рядом с полем часов видна ошибка о том, что часы не указаны

#### Scenario: Отрицательные часы или ноль
- **WHEN** в поле часов введено `-1` или `0`
- **THEN** задача не добавляется, рядом с полем часов видна ошибка о допустимом диапазоне 0,5–24

#### Scenario: Вне диапазона или не кратно шагу
- **WHEN** в поле часов введено `25` или `0,75`
- **THEN** задача не добавляется, рядом с полем часов видна соответствующая ошибка

#### Scenario: Не число
- **WHEN** в поле часов введено `abc`
- **THEN** задача не добавляется, рядом с полем часов видна ошибка «введите число»

#### Scenario: Граничные значения
- **WHEN** введены часы `0,5` или `24` при валидном названии
- **THEN** задача добавляется

### Requirement: Показ ошибок и сохранение ввода
При невалидном вводе каждая ошибка MUST быть видна непосредственно рядом со своим полем. Введённые значения обоих полей MUST оставаться в форме. Данные задач MUST NOT меняться.

#### Scenario: Обе ошибки сразу
- **WHEN** форма отправлена с пустым названием и пустыми часами
- **THEN** видны обе ошибки, каждая у своего поля, а список и сводка не изменились

#### Scenario: Ввод не теряется
- **WHEN** введено название «Практика 2» и часы `30`, затем нажата кнопка добавления
- **THEN** поле названия по-прежнему содержит «Практика 2», поле часов — `30`, видна ошибка у поля часов

### Requirement: Итоги и прогресс
Сводка MUST показывать сумму часов всех задач, сумму часов задач с `done=true` и прогресс `Math.round(100 × выполнено / всего)`. Если сумма часов всех задач равна 0, прогресс MUST быть 0%. Значения `NaN` и `Infinity` MUST NOT появляться в интерфейсе.

#### Scenario: Стартовый пример
- **WHEN** трекер открыт со стартовыми данными
- **THEN** всего 8 ч, выполнено 2 ч, прогресс 25%

#### Scenario: Пустой список
- **WHEN** задач нет
- **THEN** всего 0 ч, выполнено 0 ч, прогресс 0%

### Requirement: Фильтр влияет только на видимый список
Фильтр MUST иметь значения «Все» и «Активные» (активные — `done=false`). Фильтр MUST менять только набор видимых строк списка. Итоговые часы и прогресс MUST считаться по всем задачам независимо от фильтра.

#### Scenario: Включён фильтр «Активные»
- **WHEN** на стартовых данных выбран фильтр «Активные»
- **THEN** список показывает только «Практика» и «Повторение», а сводка остаётся: всего 8 ч, выполнено 2 ч, прогресс 25%

#### Scenario: Отметка готовности при фильтре «Активные»
- **WHEN** при фильтре «Активные» «Практика» отмечена готовой
- **THEN** «Практика» исчезает из видимого списка, прогресс 75%

#### Scenario: Возврат к «Все»
- **WHEN** после фильтра «Активные» выбран фильтр «Все»
- **THEN** снова видны все задачи из данных

### Requirement: Читаемость на 390 px
На ширине окна 390 px интерфейс MUST быть читаемым и MUST NOT вызывать горизонтальную прокрутку, в том числе при длинных названиях без пробелов.

#### Scenario: Узкий экран
- **WHEN** страница открыта при ширине окна 390 px
- **THEN** ширина документа не превышает ширину окна, весь текст и все элементы управления видны без горизонтального скролла

#### Scenario: Длинное название
- **WHEN** добавлена задача с названием из 60 символов без пробелов
- **THEN** название переносится внутри строки списка, горизонтальный скролл не появляется

### Requirement: Подписи полей и кнопок
Каждое поле ввода и каждый переключатель MUST иметь связанную подпись. Каждая кнопка MUST иметь текст или доступное имя, по которому понятно действие и, для действий над строкой, его объект.

#### Scenario: Подписи формы и списка
- **WHEN** проверяются элементы управления страницы
- **THEN** у полей названия и часов есть `<label>`, у фильтра есть подпись группы и подписи вариантов, переключатель готовности подписан названием задачи, кнопка удаления называет удаляемую задачу
