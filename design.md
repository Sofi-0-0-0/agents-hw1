# Design: add-weekly-study-tracker

## Context
Один статический файл `tracker-v2.html` без сборки и без зависимостей. Данные живут только в памяти страницы на время сессии.

## Goals / Non-Goals
Goals: точная модель данных, детерминированные расчёты, валидация с понятными ошибками, корректная вёрстка на 390 px.
Non-Goals: сохранение между перезагрузками, редактирование задач, сеть, фильтры кроме «Все» / «Активные».

## Decisions

### D1. Структура файла
`<!doctype html>`, `<html lang="ru">`, `<meta charset="utf-8">`, `<meta name="viewport" content="width=device-width, initial-scale=1">`. Один `<style>` и один `<script>` в конце `<body>`. Внешних URL нет.

### D2. Состояние (единственный источник истины)
- `tasks`: массив `{ id: number, title: string, hours: number, done: boolean }`
- `nextId`: number
- `filter`: `'all' | 'active'`

Стартовые значения:

| id | title      | hours | done  |
|----|------------|-------|-------|
| 1  | Чтение     | 2     | true  |
| 2  | Практика   | 4     | false |
| 3  | Повторение | 2     | false |

Начальные служебные значения: `nextId = 4`, `filter = 'all'`.

Интерфейс всегда перерисовывается из состояния после каждого изменения: добавление, удаление, переключение, смена фильтра. DOM не используется как хранилище данных.

### D3. Генерация id
Счётчик `nextId`, который увеличивается после каждого добавления. `crypto.randomUUID` не используется: при открытии через `file://` безопасный контекст не гарантирован.

### D4. Операции над данными
- `addTask(title, hours)`: добавить `{ id: nextId++, title, hours, done: false }` в конец массива.
- `removeTask(id)`: заменить массив на отфильтрованный без этого `id`.
- `toggleTask(id)`: инвертировать `done` у задачи с этим `id`.

### D5. Расчёты (всегда по всему `tasks`, без учёта `filter`)
- `total = сумма hours всех задач`
- `doneHours = сумма hours задач с done = true`
- `progress = total > 0 ? Math.round(100 * doneHours / total) : 0`

Все `hours` кратны 0,5, а такие суммы точно представимы в двоичной плавающей арифметике, поэтому ошибок накопления нет. `Math.round` округляет половину вверх (12,5 → 13). Ветка `total > 0` исключает деление на ноль, а значит `NaN` и `Infinity`.

Проверочные значения:

| Состояние                      | total | doneHours | progress |
|--------------------------------|-------|-----------|----------|
| Старт                          | 8     | 2         | 25%      |
| Старт + «Практика» готова      | 8     | 6         | 75%      |
| Старт + фильтр «Активные»      | 8     | 2         | 25%      |
| Старт − «Чтение»               | 6     | 0         | 0%       |
| Старт + «Тест» 1,5 ч           | 9,5   | 2         | 21% (21,05 → 21) |
| Все задачи удалены             | 0     | 0         | 0%       |

### D6. Видимый список
`visible = filter === 'active' ? tasks.filter(t => !t.done) : tasks`. Используется только для отрисовки строк. Если `visible` пуст, показывается короткий текст: «Задач нет» или «Активных задач нет».

### D7. Разбор и валидация часов
Поле `type="text"` с `inputmode="decimal"`. Это сделано потому, что `type="number"` для некорректного ввода отдаёт пустую строку, и тогда «пусто» и «не число» неотличимы.

Алгоритм для значения `raw`:
1. `s = raw.trim().replace(',', '.')`
2. `s === ''` → ошибка «Укажите часы» (пусто ≠ 0).
3. `s` не соответствует шаблону «необязательный минус, цифры, необязательная дробная часть» → «Введите число, например 1,5».
4. `n = Number(s)`; `n < 0.5 || n > 24` → «Допустимо от 0,5 до 24 ч». Сюда попадают отрицательные значения и 0.
5. `!Number.isInteger(n * 2)` → «Шаг — 0,5 ч».
6. Иначе значение валидно, `hours = n`.

Название: `t = raw.trim()`; если `t === ''`, ошибка «Введите название». Сохраняется `t`.

### D8. Ошибки формы
- Оба поля проверяются при каждой отправке, обе ошибки показываются одновременно.
- Ошибка выводится в элементе сразу под своим полем. Поле получает `aria-invalid="true"` и `aria-describedby` с id элемента ошибки.
- Фокус переводится на первое невалидное поле.
- При ошибке значения полей не сбрасываются, состояние `tasks` не меняется.
- Ошибка поля снимается, когда пользователь редактирует это поле.
- После успешного добавления поля очищаются, ошибки скрываются.

### D9. Отрисовка и безопасность
Названия задач вставляются через `textContent`, без `innerHTML`, чтобы пользовательский ввод не интерпретировался как разметка. Часы форматируются через `toLocaleString('ru-RU')`: 0,5 → «0,5», 8 → «8».

### D10. Вёрстка на 390 px
- `box-sizing: border-box` на всех элементах, контейнер `max-width` с `width: 100%` и боковыми отступами.
- Нет фиксированных ширин больше 390 px. Форма складывается в колонку на узкой ширине.
- Для названий: `overflow-wrap: anywhere`, у гибких элементов `min-width: 0`.
- Базовый размер шрифта не меньше 16 px, чтобы мобильные браузеры не масштабировали поля при фокусе.

### D11. Подписи
- `<label for>` у полей «Название» и «Часы».
- Фильтр сделан группой радиокнопок в `<fieldset>` с `<legend>Фильтр</legend>`.
- Чекбокс готовности обёрнут в `<label>` с названием задачи.
- Кнопка удаления имеет видимый текст «Удалить» и `aria-label="Удалить «<название>»"`.
- Кнопка отправки называется «Добавить».

## Risks / Trade-offs
- Данные теряются при перезагрузке. Это осознанно, сохранение вне границ.
- `type="text"` не даёт стрелок у числового поля. Взамен получаем однозначное различение «пусто» и «не число».
- Округление `Math.round` даёт половину вверх. Это зафиксировано здесь, чтобы проверки не расходились с реализацией.
